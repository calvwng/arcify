# Shift-click Little Arc and optional Peek

Shift-click link opening is opt-in and off by default. Pair Arcify and Spotlight, then enable **Shift-click links / Open Shift-clicked web links in Little Arc** in Spotlight options. A trusted Shift + primary click opens one real page through the existing Little Arc temporary-window flow, with no iframe and no automatic Space placement. Its existing header can place that same native page in a selected Space. Existing `peekEnabled: true` users keep their opt-in but now get Little Arc; absent/false remains off. The separate `peekIframeEnabled` setting defaults false. Enable **Use iframe Peek instead (experimental)** to restore the optional preview described below. Changing either setting invalidates pending and active source sessions.

Only ordinary HTTP(S) anchors in the main webpage are covered. Plain clicks, other modifiers, downloads, editable controls, named-frame links, child frames and extension pages retain their existing handling. Sidebar Shift selection is unaffected. A page's earlier window-capture handler can prevent the extension from seeing the event. Existing pages may need reloading after extension updates; no content-script sweep is performed. Before the local opt-in has been read, native handling remains unchanged. Use the existing Little Arc link context menu where interception is unavailable. Pinned/Favorite source pages are supported without moving or unpinning them; transient, private and non-normal source windows are rejected.

Once opt-in is known, an eligible click prevents native Shift-click immediately, including during a cold connection. Visible connecting feedback holds one immutable link intent for at most 2.5 seconds. Readiness can continue that single gesture only while the source URL, connected link URL/eligibility, mode and focused visible document remain valid. Focus loss, timeout, navigation, disconnection, settings changes and link replacement cancel it without opening. The intent is cleared before dispatch. Initial handshake failure can recover on a later genuine pointer/focus/Shift-click even if readiness has never succeeded. Recovery is read-only until a fresh trusted gesture; no native action is retried. Unavailable feedback explicitly says when no action was sent. A dispatched uncertain action retains the existing durable receipt guard and recovery instructions.


**Open in current Space**, beside **Close Peek**, opens the validated current preview URL anew and files the resulting native tab into the originating normal window's current Space. Arcify reads its authoritative active Space at action time, with no fallback to the source tab's owner or first Space. Space/folder/window identity remains checked before dispatch. **Open in Little Arc** uses the same validated URL in the existing temporary-window flow. When a current URL is unavailable, both actions explicitly use the original link; the address and action status disclose this. A failed fresh sample of a bound document never silently becomes a stale/original guess. Both actions are explicit; frame load, failure, navigation, hover, selection and heartbeat cannot open native pages.

Expansion reuses `transientWindows.openUnlocked`, `promoteUnlocked`, the existing ownership commit adapter, and exact-controller cleanup. It creates one real web tab and moves that same native ID; a temporary controller/window may briefly appear. Persisted unique Space membership, snapshot membership and the transient journal must be confirmed before success is returned. Unknown creation/movement/persistence results retain existing transient quarantine. No automatic retry, second create, compensating move, URL-based tab selection, or rollback is attempted. Existing Little Arc trusted controls remain the recovery interface.

Close dismisses the preview and restores the clicked link's focus when its source document still exists. Once an opening action has been sent, Close cannot undo it: the action may finish after dismissal. Before native dispatch, loss of the source document, pairing, runtime connection, window or active Space fails closed. After move dispatch, exact destination ownership can finish if still valid; otherwise the native page is preserved under quarantine. A completed page is never silently recreated. Source navigation, BFCache suspension, fullscreen entry or removed host invalidates the instance. The expected source focus/visibility loss caused by our own window creation and tab movement does not invalidate an already admitted action.

`peekOperationsV1` in Arcify's `storage.session` stores a bounded suppression receipt before any native create. Its `url` remains the original link, while new receipts add `targetUrl` for the immutable URL actually selected. Legacy v1 records without that field remain valid, unchanged and suppressive. A pending or completed-but-unacknowledged receipt blocks another Peek operation for the same source tab/window/source URL and original target URL, including after worker restart, closing/reopening Peek, or a lost reply. A new action for that same source also cannot dispatch to a destination already held by such a receipt. This is bounded uncertainty suppression, not global URL deduplication or authority to replay. Only content receipt of a confirmed successful result permits acknowledgement cleanup. Lost acknowledgement cleanup preserves the visible fact that the page already opened. Uncertain receipts intentionally remain for the browser session; inspect existing Little Arc controls and native windows. The receipt complements, and does not weaken or repair, the transient journal. It is not a promise of cross-browser-restart deduplication.

Authority stays in isolated content closures and extension workers. Only a browser-attested top-frame runtime Port can prepare an instance; paired Arcify validates the broker and requests a fresh document/action proof. The original link remains immutable in Arcify. At action admission a separate selection is frozen: mode, HTTP(S) URL, browser frame ID, optional browser document ID and fresh private binding revision. Every authority guard requires the same selection. Original mode must match the prepared original URL exactly; current mode requires the exact live observer/extension-wrapper binding and a fresh isolated location sample. Version 3 capability negotiation and the strict proof schema reject mixed old/new pairs.

Spotlight's extension wrapper is bound by a single-use nonce delivered privately to the top content script and sent only to its stored wrapper WindowProxy at the exact extension origin. An isolated child observer receives another nonce privately and sends it only to its immediate extension parent; the wrapper requires the event source to equal its stored direct child. Responses return over authenticated runtime Ports. The web page never receives these nonces, and arbitrary/nested frames or a matching web-accessible URL cannot claim authority. Optional document IDs strengthen browser identity when available; fresh Port and binding revision checks still prevent stale document replay when the field is absent. The parent/source URL is not sent through query parameters or referrer (`no-referrer`). URLs are necessarily present in the child's `src` and visible address labels.

The extension wrapper contains a web iframe sandboxed with `allow-scripts allow-forms` and an opaque origin. It cannot navigate the top page, open popups, download, or gain same-origin parent access. Autoplay, camera, microphone, location, payment and fullscreen are disabled. No API/host permissions or response/security headers change. A small static observer is added for HTTP(S) frames under the existing content-script site access; it is inert unless its immediate ancestor is this extension. CSP/X-Frame-Options apply across the full ancestor chain, including the outer webpage. Third-party restrictions, storage and authentication requirements can still block or degrade the preview. Frame load/error events cannot determine successful rendering; fallback stays visible. Current URL tracking covers redirects and browser-permitted History/hash changes, using a 250 ms bound-document poll plus fresh action/guard samples. Forms, JavaScript state, history, scroll and authentication state are not transferred. Normal browser cookie policies and opaque-origin History restrictions still apply. The prototype does not bypass authentication or embedding restrictions.

The closed shadow tree and top-layer modal protect controls from routine page CSS and synthetic clicks; fresh foreground trusted gestures are required. They are not a privileged browser surface. A hostile webpage can interfere with an embedded interface or attempt clickjacking. Use trusted extension/Little Arc controls for sensitive actions.

Only a mounted idle preview sends a read-only heartbeat every 15 seconds. It stops on action, dismissal, failure and navigation, cannot create or rearm an operation, and cannot extend the original 30-minute authority TTL. If an idle no-preview worker disconnects, a subsequent real pointer/focus gesture can warm read-only capability (at most two failed attempts, reset after readiness). Known opt-in cold clicks use the bounded intent described above; unknown or disabled opt-in preserves native behavior. Unexpected disconnect with an existing preview fails closed rather than reconnecting its operation.

Focused coverage: `tests/unit/peek.test.js`, Peek cases in `tests/unit/transient-window-integration.test.js`, and Spotlight `test/unit/peek.test.js` / `test/unit/peek-preview.test.js`. The exact current document must complete loading before binding; load and navigation signals conservatively retire bindings rather than granting opening authority. Existing transient, direct placement, shared Today and recovery suites remain applicable. Native Chromium testing must separately verify framing, redirects, current-URL opening, trusted input, focus and extension lifecycle; a debugger-attached worker may stay alive, so a long preview wait alone does not prove real worker suspension.
