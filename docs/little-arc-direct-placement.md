# Optional direct Little Arc placement

Trusted confirmation is the default. In the existing Little Arc control tab, expand **More: direct placement**, read the clickjacking explanation and explicitly enable direct placement. Enabling the setting does not transfer a page. Return to its header and refresh choices. The header then offers **Open in [Space]**; **More** retains window choices and trusted controls.

The selected destination is provisional metadata until an explicit genuine submit. Selection, refresh, hover, navigation and connection renewal never transfer a page. The displayed selection does not expire while reading. Open re-reads the current choices and obtains a fresh, broker-held, single-use authorization immediately before dispatch. The backend authorization still has a short 15-second execution deadline; it is not a pre-click countdown. Safe refresh retains the exact selected window, Space UUID and bookmark-folder identity. An invalid retained choice stays unselected and requires an explicit choice, rather than reverting to a default. Missing/closed/changed destinations never silently fall back. There is no Undo or automatic compensating transfer.

A private one-use challenge binds only the registered extension header instance to the tracked top-frame page. Direct authorization is held only by the broker/backend, bound to page/native IDs, pairing generation, connection and chosen destination, and consumed before the first execution await. The backend rechecks opt-in, expiry, current header authority, exact native page and destination under the existing store queue. A fresh frame-0 content-script probe verifies the active top document's private connection challenge, URL, focus and presentation. Page navigation/detach/replacement/disconnect retires authority. Fresh source event fences cover awaited validation. Existing pin/Favorite/Split, ownership, persisted moving journal, admission and readback checks remain in use.

Visibility, focus, fullscreen and occlusion checks are defense in depth. Extension-origin iframe and closed Shadow DOM do not make this browser chrome. A hostile website may reposition or obscure the embedded header and trick a real click. This accepted residual risk does not grant websites command authority. The privileged setting and fallback controller are not web-accessible frames.

Successful placement uses the same native tab, confirms saved Today membership and the transaction journal, then activates the destination and reads back focus. Only its exact unchanged, unpinned, non-Split controller tab may be closed. Other pages are preserved; the empty temporary window closes naturally. Focus/cleanup failure does not undo a committed placement or invite a repeat. A navigation or closure after the final native call remains a platform race; there is no atomic transaction spanning browser UI and extension storage. An uncertain result retains existing quarantine/read-only reconciliation semantics with no automatic replay. The expected native move disconnects the header, so completion does not depend on delivering its final iframe reply.

Restart durability, hostile-page presentation heuristics and interrupted-process acceptance require separate native evidence. Unit tests alone do not establish them. No user profile or browser state is modified by building this candidate.

The broker claims each Open synchronously before awaiting validation. A session-storage fence, containing only native IDs and an operation identifier, is confirmed before dispatch; it survives worker reconnects and prevents another header transfer after a lost or uncertain reply. A proven failure before send may retire only its own fence. After send, choices refresh cannot clear it. Confirmed exact commit or native tab removal retires the matching fence. Storage failure fails closed. This supplements the existing Arcify moving journal; it does not replace reconciliation or establish full-browser restart durability.
