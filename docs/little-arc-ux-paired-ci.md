# Little Arc sizing and source dimming acceptance

`.github/workflows/little-arc-ux.yml` adds a separate hosted job for the same-fork `feature/little-arc-size-preview` pull request into `main`. It checks out the actual PR head, not GitHub's synthetic merge, and pins Spotlight to `1ec956febfb0ce83f02ff5daf904e060d4e35948`. A separate context validator checks the real event file, repository, head/base branches, PR identity, full commit IDs and explicit UX flag. Existing paired jobs, pins, scope selection and acceptance guards remain unchanged.

The job uses the existing locked driver, installed Chrome, ordinary non-root runner, fresh disposable profile, Xvfb and namespace/PID/network/seccomp sandbox verification. It neither repairs browser policy nor retries a failed browser launch. Source and build hashes are retained before launch; evidence uploads run after success or failure.

The existing Little Arc launch, exact native document, promotion and full-extension reload regression chain remains selected. Two additional feature exercises run after its first trusted launch:

* Sizing uses real controller input to enable size memory, edit fixed dimensions, Preview two distinct sizes, Cancel back to the exact original outer bounds, Preview again and Save. Native window reads establish actual sizes. A passive storage event ledger proves no observed preference change during either Preview or Cancel, including the memory debounce period; only explicit Save commits a preference. A trusted Reset restores disposable future-window defaults before the later launch cases.
* Dimming uses actual Spotlight option checkboxes and genuine Shift-click on a nonce fixture link. Exact source IDs, a completed Peek operation receipt, the single new ready transient record and two fresh native targets establish destination ownership before observation or cleanup. The original source document receives a noninteractive dim while its destination window is focused; an unrelated existing Little Arc page does not. Returning to the source delivers a checkbox click through the overlay and clears it without replacing the source document. A second launch with dimming disabled remains undimmed. Exact fixture windows are closed only after their owned native IDs are checked.

All served content and retained observations are synthetic. Page/API evaluation supplies passive observations and existing fixture cleanup/setup only; it does not inject successful feature responses, dispatch product geometry requests, set preferences behind the UI, synthesize DOM gestures, or substitute mocked geometry for native outcomes. This job does not validate Helium, user profiles, real YouTube playback, mixed-DPI hardware, full OS restart or every interruption boundary. Those limits must remain explicit even when this hosted job passes.
